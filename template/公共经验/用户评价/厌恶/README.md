# 厌恶（这条路走不通）

> **目的**：记下**被明确否掉的做法**。这是整个库里最值钱、也最容易被忽略的一类。

## 命名

`<项目>-<日期>-<短标题>.md`。短标题写"被否掉的是什么"，不写情绪词。

## 每条必须写清三样

1. **被否掉的是什么**（范围：整套方向，还是某个按钮）
2. **错在哪一层**（理解错目标 / 形态选错 / 只修了一半 / 流程失守）
3. **以后怎么避免**——写成**可执行的判据**，不写"下次注意"

> `下次注意` 是无效条目。它不告诉你下次怎么判断。

## 可迁移形式

条目末尾写一段"可迁移形式"：去掉项目专名仍然成立。

写不出来的，说明这条只是这一次的意外，价值有限。

## 使用

用之前必须过 `../README.md` 第零节的审视。
