# Agent Memory System

> 一套**文件夹约定**，让 AI 在不同会话之间记住：你在做什么、为什么这么做、以前踩过什么坑。
>
> 没有数据库、没有向量检索、没有 SDK——只有 Markdown 文件，和一份开工前读什么的清单。

---

## 它解决什么问题

每次开新对话，AI 都从零开始。

你花三天教它的规矩、它犯过的错、这个项目为什么改成现在这样——全部锁在那一个对话窗口里。关掉就没了。下次要重新讲一遍，而且讲不全。

现有解法各有代价：

| 做法 | 问题 |
|---|---|
| 全塞进系统提示 | 越写越长，最后连自己都不看；改一句要动全局 |
| 向量库检索 | 要跑服务、维护索引；检索出来的是"相似文本"，不是"当时为什么这么决定" |
| Agent 框架 | 绑定运行时。换个工具、换台机器，记忆就带不走 |

这套东西的取舍是：**牺牲自动化，换取可携带。**

---

## 三条主张

### 1. 文件即记忆

记忆是 Markdown 文件，不是数据库里的行。

好处很实际：能 `git diff` 看它怎么变的、能直接打开读、能随手改一个字、能被任何工具读取。AI 读文件和读网页没有区别，但**你能审**。

### 2. 分层按需读，而不是全塞进上下文

大多数方案想的是"怎么把更多东西压进窗口"。

这套反着来：**先给一个入口，让人（和 AI）自己挑该读哪几份**。

```
入口（README）→ 开工清单 → 只读这次相关的那 2~3 份
```

代价是清单必须写全——**清单漏掉一类文件，那类文件就永远读不到**。这是它最脆弱的地方，所以清单本身也要被维护。

### 3. 记错误，不只记成功

绝大多数知识库只记"怎么做对"。

但真正让人反复踩坑的是：**某些做法曾经被明确否掉过，而没人记得为什么。**

所以这里有一个专门的目录存"负面资产"：不是"最佳实践"，是"这条路走不通，以及为什么"。

## 长什么样

```
记忆/
├── README.md                 入口：我该看哪份？
├── 全局工作流.md             规则①：做事的顺序（先做什么、交付什么）
├── 全局公约.md               规则②：产出必须是什么样
├── 全局工作提示.md           规则③：哪类活用哪个工具
│
├── 公共资产/                 【跨项目复用】换项目还一样的东西
│   ├── 操作手册/             怎么做：分主题的操作说明
│   ├── 自总结sop/            跨项目一样的流程
│   └── 插件/                 技法参考 / 第三方工具登记 / 代码快照
│
├── 公共经验/                 【跨项目经验】
│   └── 用户评价/
│       ├── README.md         使用约定 + 索引
│       ├── 厌恶/             这条路走不通
│       └── 夸奖/             这类活该怎么做
│
└── 项目/                     【每个独立的工作单元】
    └── <项目>/
        ├── 项目档案.md       目的是什么、给谁做、演进过程
        ├── 项目公约.md       这个项目的硬约束
        └── 项目资产/
            ├── 用户提问原文.md   用户原话（逐字）
            ├── 验收清单.md       验收清单
            ├── 思考产物/         思考过程（.md）
            ├── 过程产物/         中间产物（脚本、数据、截图）
            └── 成果产物/         交付物
```

（英文目录名不是必需的——换成 `memory/`、`rules.md`、`projects/` 一样能用，AI 不挑名字。）

## 怎么开始

**三步，十分钟。**

1. **复制 `template/` 到你想放的地方**，改名为你的记忆库目录。
2. **填三样**：
   - `conventions.md` —— 你自己做事的顺序（先了解需求、还是先动手？交付前要检查什么？）
   - `principles.md` —— 做出来的东西必须满足什么（可以先空着，边做边加）
   - 第一个项目的 `profile.md` —— 这个项目要达成什么、给谁用
3. **在每次对话开头说一句**：

   > 先读 `<路径>/README.md`，按里面的开工清单来。

之后它自己会长。

## 它和 agent harness 是什么关系

2026 年 "harness" 成了固定说法：**模型之外的运行环境**——主循环、工具、上下文管理、权限、沙箱、子代理。

| 层 | 管什么 | 典型项目 |
|---|---|---|
| **harness** | **单次任务怎么跑稳**：循环、工具注册、上下文压缩、权限门、沙箱、checkpoint | Claude Code、Codex CLI、OpenHands、Aider、SWE-agent |
| **这套东西** | **跨会话怎么不重犯**：目标为什么变成这样、哪些做法被否过、教训存在哪 | 本仓库 |

两者不冲突，职责不同，而且**互补得很具体**：

| 场景 | harness 怎么处理 | 这套东西怎么处理 |
|---|---|---|
| 上下文快满了 | 自动压缩 / 子代理隔离 | **一开始就不全读**，分层按需读 |
| 要求"别改 .env" | 权限门 + hook 硬拦 | 写进规范，靠自觉（弱） |
| 长任务中断 | checkpoint / transcript 落盘 | 验收清单 + 档案，人可续 |
| **"这个项目为什么改成现在这样"** | 通常不记 | **演变链，只追加不覆盖** |
| **"这个做法以前被否过"** | 通常不记 | **负面资产，独立目录** |

最后两行是关键差异。

harness 的记忆通常是 **session transcript**——这次聊了什么，可以重放。
这里记的是 **决策与否证**——为什么这么定、什么不能做，用来防止回退。

一个真实场景：三个月后你（或另一个 AI）回到这个项目，看到当前状态，觉得"这里绕了一圈，简化掉吧"。
transcript 里没有"为什么绕这一圈"，于是改回去，把已经解决的问题重新炸开。
**只有演变链能挡住这个。**

### 所以它们的边界刚好互相对应

- **harness 管"做不到"**：某个操作用不了、上下文不会溢出、崩溃后能恢复；
- **这套文件管"记得住"**：目标、决策、教训。

这套东西的**最大弱点**（不强制、靠 AI 主动读）正好是 harness 的**强项**，
而 harness 的**最大空白**（不记决策与否证）正好是这套东西的**强项**。

**所以最好叠着用**：用 harness 挡住硬错误，用这套文件记住软经验。

> 如果你的环境支持 hook，一个很值钱的组合是：
> 在「准备结束任务」这个时刻挂一个检查——**交付物是否已入库 / 是否漏读了经验索引**。
> 这样"靠自觉"的部分就有了物理落点。

## 它不解决什么

写清楚边界，比列优点重要：

| 不解决 | 说明 |
|---|---|
| **不自动执行** | 不会强制 AI 遵守。靠它读了文件并照做。这是它最大的弱点——也是它能跨任何工具的原因 |
| **不替代会话记录** | 它记的是**决策**，不是聊天历史。别指望它复原"我们上次聊了什么" |
| **不是框架** | 没有 SDK、没有 API、没有运行时。AI 换成任何一家都能读，但也没法替你调工具 |
| **不会自己整理** | 目录会乱。需要人（或 AI）定期归位，这是维护成本 |

如果你要的是"自动拦截、不能出现某种操作"——那是 harness 层面的 hook 和权限门，不是这套文件能做的。两者可以叠加，但职责不同。

## 可选包（默认不启用）

`optional/` 下是作者自己在用的完整规则集：

- `optional/conventions/` —— 23 条写作与协作准则（怎么描述人、怎么设计界面、给 AI 写指令）
- `optional/playbooks/` —— 分主题的操作说明

**默认不启用**，因为规则越全，理解成本越高。建议先用空模板跑几个项目，等**你自己开始重复同一条要求**时，再回来抄对应那一条。

启用方式：把想要的文件复制进你的库，并在 `README.md` 的索引里登记一行。

## 设计上的几个取舍

**为什么不用数据库？**
因为记忆的价值不在"存得住"，在"**能被人读和改**"。一个你不敢改的记忆系统，最后一定会和事实脱节。

**为什么把"错误"单独放一个目录？**
因为正向做法可以从任何地方学到，而**否定性结论只存在于特定的人与项目的交互里**——"这个方案在这个项目上被否了"，外部搜不到。

**为什么强调"演变链"？**
只记当前状态，三个月后没人知道为什么是现在这样；于是有人会改回去，把已经解决的问题再犯一遍。记 `A → B（原因）` 比记录 `B` 贵不了多少，但能挡住这种回退。

**为什么要写"不给 AI 看"的说明？**
每份文件开头都有"这份文件是为了什么"。因为读它的是 AI，而 AI 不会问你为什么定这条规矩——它只会照做或者瞎改。写上目的，它才知道什么时候该变通。
